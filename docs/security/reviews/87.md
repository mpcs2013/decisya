# Security review – issue #87: BFF Redis `localhost` resolves to IPv6 first in local dev

- Mode: bug-fix path. This is one diff review (G6) plus the G3 `N/A` line.
- Scope: `git diff origin/main...HEAD` (1d168e2): `src/Decisya.Bff/Session/RedisRegistration.cs` (`RewriteLocalhostEndpoints`), the new tests `RedisLocalhostEndpointRewriteTests`, `RedisLocalhostLoginTests`, the `RedisFixture` and `BffFactoryFactory` test helpers, and the `docs/ai/pipeline/87.md` manifest. The working tree is clean. No new dependency.
- Question: could the rewrite send BFF Redis traffic (session tickets, Redis AUTH) anywhere other than intended, weaken the fail-closed timeouts, or matter outside local development?

## Assessment

- **Destination.** Only a `DnsEndPoint` whose host is exactly `localhost` (case-insensitive) is rewritten, to `IPAddress.Loopback:<same port>`. Hosts like `localhost.evil.com`, other host names and IP endpoints are not touched (the tests cover the last two). `127.0.0.1` is a loopback address of the same machine that `localhost` already names, so traffic cannot leave the host. The rewrite skips DNS and hosts-file lookup for this one name, so it takes nothing from a resolver and can only narrow where traffic goes. Password, user and other options are kept as they are.
- **Fail-closed.** `ConnectTimeout`, `SyncTimeout`, `AsyncTimeout`, `AbortOnConnectFail = false` and `IncludeDetailInExceptions = false` are unchanged and still set before the rewrite. If Redis listens only on `::1`, the connection is refused and the ticket store still fails closed.
- **TLS.** If `ssl=true` is used with `localhost` and without `sslHost`, certificate name validation now checks against `127.0.0.1`. A mismatch makes the connection fail, which is the safe direction. The BFF has no custom certificate-validation callback.
- **Outside local dev.** The rewrite runs in every environment but has no effect unless the configured host is literally `localhost`. A deployed Redis uses a service name, so nothing changes. A same-host sidecar addressed as `localhost` would stay on the loopback.
- **Logging and secrets.** The change adds no logging. The test connection string contains only a port.

## Findings

None that change the merge decision.

Out of scope (not re-audited): the rest of the #18 BFF session design, cookie flags, antiforgery and the ticket store.
