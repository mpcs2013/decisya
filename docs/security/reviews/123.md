## 2. F-123-S2 (tunnel-proxy key in public logs) and the other `diagnose()` output

- **The fix is complete.**
  - `diagnose()` selects containers by an allow-list (`keycloak-` and `aspire-container-network-tunnelproxy-` prefixes plus a strict name regex). For the tunnel proxy it prints only `docker port` and the state, never its logs (`fullstack.py:651-667`; test at `:302-319`). A renamed proxy container would be skipped entirely, because selection is an allow-list.
  - The new needles (PEM header, base64 `LS0tLS1CRUdJTi`, `_key_base64`, and `"server|client|private_key"`) live in the shared `PATTERN_NEEDLES`. They therefore apply to the log tail, `diagnose()`, `run_bounded`'s live streams, and the artifact scan (test at `:292-300`).
  - The deletion of the run log and the cached copies is recorded with Marco's approval. Spikes 3 and 4 found no secret pattern in the run log.
- **The other diagnostic output carries no secret:**
  - `docker ps` has a fixed `--format` (name, image, status, ports).
  - `docker port` prints only the port mappings.
  - `docker inspect` has a fixed `--format` that reads only `.State` (a full inspect would print Keycloak's env), but no test pins that format: G6-123-03.
  - Keycloak's last 100 lines: Keycloak 26 does not log its bootstrap admin password, the database passwords or client secrets at INFO. Every generated value is a literal needle in any case, and tokens and Keycloak cookies are pattern needles.
  - The remaining unneedled values are Aspire's own `OtlpApiKey` and `DashboardApiKey`. I know of no path that prints them, and they die with the runner (backlog B-1).
  - The probes report only a status code or an exception class.

## 3. The two test-code changes

- **`SpaPackageTests.cs:93-124`, the narrowed #102 guard.** Sound:
  - `\bnpx\b(?!\s+--no-install(\s|$))` refuses a bare `npx`, `--yes` and `--no-installx` (theory at `:113-120`).
  - `playwright install` must appear exactly once in `ci.yml` and once inside the `e2e` job. The job slice fails closed when `e2e:` is missing.
  - With npm 7 and later, `--no-install` maps to `--no`: it never fetches outside the lockfile.
  - The narrowing is an accepted change of #102's M1 under G4-123-04 b.
- **`AppHostResourceTests.cs:59-66`, the per-run OTLP key.** Sound:
  - `RandomNumberGenerator.GetBytes(32)`, hex, is passed as an in-process builder argument, never logged or asserted on.
  - The assertions stay names-only (`keys.Should().Contain(...)`, L-1), so a failure message cannot print the header value.
  - It removes the test's dependency on the developer's user secrets.
