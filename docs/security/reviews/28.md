## Checks the orchestrator asked for

- **No seeded package runs.** NuGet: `dotnet restore` only, into an isolated `--packages` folder and `ArtifactsPath`, deleted afterwards. Never built. npm: `--package-lock-only --ignore-scripts` in a temp directory outside the repository, so no tarball and no lifecycle script. The script refuses a work directory inside the repository. No other step references the canary projects.
- **Canary cannot pass silently.** NuGet needs a non-zero exit, an `error NU1903` or `NU1904` line, and only `Newtonsoft.Json` named. It inherits the real `Directory.Build.props` and `Directory.Packages.props`, so weakening the real policy turns it red (the `--weaken-for-evidence` evidence shows this). An unreachable audit source (NU1905, a warning) gives exit 0, which counts as FAIL. npm: a non-zero exit plus `lodash` at high or critical in the same JSON. The residuals are F-03 and F-04: the npm canary is not tied to the real audit step, and the npm path is not run when only the canary script changes.
- **`image_scan.py` cannot pass while scanning nothing.** `parse_targets` needs exactly the three aliases, each digest-pinned. Any scanner exit other than 0, non-JSON output or provenance problem goes to `failed`, which means exit 1. An empty catalogue fails on layers or distro. A missing database block fails. Any exception falls to `main()`, which returns 1. A configuration error returns 2. The only route to a skip is the step `if`, which is tested, and the weekly schedule always gives `ALL`.
- **Exceptions cannot be abused.** Every key is required and no extra key is allowed. `added` cannot be in the future, and an entry lasts at most 90 days. Ids, packages and issues are strictly formatted. Duplicates are rejected. Matching is exact on image, package and id, or on a related id of the same match. An expired entry is not applied and is listed. `.github/image-scan/**` is now a review-required path (`gates.py:321`), so every renewal goes through G3 and G6.
- **Log and command injection.** All scanner-derived and file-derived text is printed inside `::stop-commands::<token_hex(16)>` with Unicode category C escaped. The `::error::` lines outside the window are fixed strings with counts. Nothing is written to `GITHUB_ENV` or `GITHUB_OUTPUT`. The summary cells are entity-escaped. Every subprocess call uses an argv list with no shell.
- **The guard tests fail closed.** I read the detector red cases: tag, branch, short SHA, a missing or wrong comment, a job-level reusable workflow by tag, `docker://` by tag, quoted, expression and flow-mapping values, and a tag or bare-SHA pre-commit `rev`. An unreadable `uses:` or `rev:` line is flagged. A `>-` block value falls through to the pin regex and is flagged. Gaps: F-01, plus backlog B-1.
- **Ruleset and runbook.** `main.json` adds `image-scan` with `integration_id 15368`; `FLOOR` adds it; `test_ruleset` covers the no-job-level-`if` rule with a new red case. The runbook order is correct: the context reports on `main` first (the merge push changes `ci.yml`, so the scan really runs), then a dispatch run, then apply, then verify the six contexts. Only Marco applies the ruleset: "Agents never run steps 4 and 5", and the apply uses Marco's own `gh` login. One runbook error is F-05.
- **Workflow syntax (actionlint not available; read by hand).** `defaults.run.shell`, `schedule` cron, `workflow_dispatch: ` with no value, job `permissions`, `queries: security-extended`, `needs.changes.outputs.images` (declared in `outputs`) and the concurrency expression are all valid. The only `${{ }}` inside `run:` are the pre-existing `true`/`false` lane outputs. Under the new `-eo pipefail` default, every pipeline in the lanes block is guarded by `|| true` and every `[ ] && …` list is non-final, so `changes` does not newly fail. No finding.
- **Tests run:** `python -m unittest test_ci_pins test_ci_gates_fail_closed test_gitleaks_parity test_ruleset` gives 54 tests, OK.
