## Findings

| Id | Severity | Finding | Fix | Disposition | Status |
| --- | --- | --- | --- | --- | --- |
| G6-58-01 | **Medium** | **`-v` / `--version` lets the agent run any npm verb.** `_NPM_ALLOWED_VERBS` accepts `-v` and `--version` as the "verb", and nothing checks what follows. npm's option parser (nopt) takes a following `true`/`false` as the value of a boolean flag, and the next positional becomes the command. Verified on the host: `npm --version false prefix` passed the hook (as security-reviewer, a listed agent) and npm ran `prefix`; `npm -v false config get ignore-scripts` ran `config`. So `npm --version false install <pkg>` and `npm -v false ci` pass `npm_violation` (it returns `None` for both) and install. This defeats M1 with one extra token. An injected instruction can carry it, and the hook was built to stop exactly that. | In `npm_violation`, accept `-v`/`--version` only as the **last** token of the segment, for example `if verb in {"-v", "--version"} and len(rest) > 1: return ...`. Or drop both from the allow-list, since agents have no need for them. Add `npm --version false install x`, `npm -v false ci` and `npm -v true i x` to `DENIED` in `test_npm_guard.py`; red before the fix, green after. | **fix-now** | **Fixed** (re-check). `-v` and `--version` are removed from `_NPM_ALLOWED_VERBS`, with a G6-58-01 comment, and the deny reason no longer lists `npm --version`. `npm --version false install x`, `npm -v false ci`, `npm -v true i x`, `npm -v` and `npm --version` are now in `DENIED`, and the probe returns a violation for each. The allowed verbs still pass, and `audit fix` is still denied. `test_npm_guard.py`: 6 tests OK. |
