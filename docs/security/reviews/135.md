## 2. Index parser against Git's format

- **Header and versions:** `DIRC`, a 4-byte version and a 4-byte count are correct. Versions other than 2, 3 and 4 give None.
- **Entry layout:** mode at offset 24, flags at 60 to 62, and a 62-byte fixed part are correct for SHA-1. The extended flag (`0x4000`) adds 2 bytes only for v3 and later, which is correct. An extended bit set in v2 is invalid in Git. Here it is ignored, and only a crafted index with a valid checksum would reach this. No impact.
- **v2/v3 padding:** `start + ((end - start) // 8 + 1) * 8` equals Git's `(62|64 + len + 8) & ~7`, so 1 to 8 NULs. Correct.
- **v4:** there is no padding. The strip-length varint in `_index_offset` matches Git's `decode_varint` (`(value + 1) << 7 | next`). Python ints cannot overflow. A runaway varint ends in an `IndexError`, which is caught. `strip > len(previous)` gives None. Covered by the v4 subtest (shared `.claude/skills/` prefix).
- **Name length:** the parser searches for the NUL instead of trusting the 12-bit length. This is correct for names of 0xFFF bytes or longer.
- **Sparse index:** a directory-mode entry (`040000`) or an `sdir` extension gives None. **Split index:** `link` gives None.
- **Extensions:** they are walked as 4-byte signature plus 4-byte size until the trailer. A size that overruns, or 1 to 7 trailing bytes, gives `pos != body_end`, so None. Unknown extensions (`TREE`, `REUC`, `UNTR`, `EOIE`, `IEOT`, `FSMN`) are skipped by size, which is correct.
- **Trailer:** SHA-1 over everything except the last 20 bytes. A SHA-256 index (a 32-byte trailer, 32-byte ids) also fails this check, so the `objectformat` check in config is defence in depth. In a linked worktree it reads the private gitdir's config, not the common one, but the trailer check still rejects SHA-256.
- **Malformed input:**
  - A count larger than the data: every entry advances at least 62 bytes. Slices past the end read as 0, and `data.index` raises `ValueError` or `pos > body_end` gives None. The loop is therefore bounded by the file size, not by the count, so a count of 2^32-1 is harmless.
  - Invalid UTF-8 in a path: `decode` raises, the error is caught, and the result is None. This is safe, but any non-UTF-8 path anywhere in the repository turns the filter off (B-1).
  - An entry truncated before the trailer: `pos > body_end` gives None.
- **Does "catch everything and return None" hold?** Yes. All of `_git_dir`, the config read, the index read and the parse sit inside the `try` of `tracked_paths` (`roster.py:137-179`). `MemoryError` and `RecursionError` are `Exception` subclasses. The only new code outside the `try` is `path.relative_to(root).as_posix()` on paths that the glob under `root` produced, and that cannot raise. The one gap is that the read has no size cap (G6-135-01).

## Backlog (to #83; none changes the merge decision)

- **B-1: silent fallback cases that bring the bug back.**
  - Git's `index.skipHash=true`, which `feature.manyFiles=true` turns on in current Git, writes an all-zero trailer. The SHA-1 check then rejects it, the filter is silently off, and the local skill again makes `--check` stale. The `RosterTreeTests.setUp` copy (`test_roster.py:34-37`) then copies every skill, so the 7 test failures come back.
  - A non-UTF-8 path anywhere in the index has the same effect.
  - Options: accept an all-zero trailer when the rest of the parse ends exactly at `body_end`, and decode with `errors="surrogateescape"` (membership is only checked for ASCII skill paths). Add S-3's one stderr line whenever a `.git` exists but the fallback is taken.
- **B-2: G4-135-04 check as behaviour, not source text.** `test_roster.py:427` checks that `lint.py` contains the glob string and not `tracked_paths`. It would still pass if lint filtered skills through `roster.read_sources` or another helper. Replace or extend it with a lint run on a temporary tree that has a fixture index and an untracked skill containing a `RISKY_INSTRUCTIONS` line, and assert that lint reports it.
- **B-3: S-4.** Add to the `roster.py` docstring Sources line (`:8-10`): "skills limited to paths in the git index when the index is readable (#135)".
