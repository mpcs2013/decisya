## Effect of the 15 core files on Decisya

Nothing here needs a code change in this PR. The items that need a record are in the backlog list.

- **`agents/security-reviewer.md`.** Adds the "File and folder access" check (paths a program walks or opens, name collisions, links, junctions, network shares, the secret guard's folders, every path with the same exposure). The G3/G6 tool line is unchanged. The addendum does not conflict.
- **`rules/core.md`.** A bundle is installed only after `notice: ok` against a fresh snapshot, from the next bump on with the snapshot's own `lock.py notice` taken from the snapshot commit and run with `python -I`. This bump met it with the fixed checker (0.4.1 has no `notice` command). The security-reviewer may not run `git show`, so the main session must take that copy; G3 S-7 already records the ADR-0023 §7 follow-up.
- **`skills/issue/SKILL.md`.** Adds `--plan-epic` (planning pack, not installed: `gates.py init` refuses it) and an input line for G1 when the manifest records `- Epic:`. The G3/G6 prompt text is unchanged.
- **`_claudecfg.py`, `commitlint.py`, `gates.py`, `lint.py`, `prepush.py`.** `git` (and in `lock.py` `ssh-keygen`) now starts only from an absolute PATH entry outside the repository, `.exe` only on Windows, never UNC, with `NoDefaultCurrentDirectoryInExePath=1` set for the process and its children. It fails closed. On the CI runners (`ubuntu-latest`, `/usr/bin/git`) and in Git's hook PATH it resolves; the pre-push run as a hook and CI's commitlint mirror (`ci.yml:251`) use it.
- **`gates.py`.** The notice-signers file joins the review-required floor automatically. An unread tier line that does not say "light" is now a `NOTE` and counts as Full (the stricter tier) instead of a failure; one that says "light" still fails. `test_manifest_tiers.py` passes unchanged (G4).
- **`lint.py` (runs in CI, `ci.yml:290`).** Two new problems from 0.5.0:
  - the notice-signers file missing or not the derivation of the signers file. Any later edit of `.github/allowed-signers/norma` (a rotation) fails CI unless `lock.py notice-signers --write` runs in the same PR;
  - any `--revoked` spelling (`--re` up to `--revoked`) anywhere under `.github/`, in any file, that is not a followed `--revoked <file>` on a `lock.py verify` call, while `lock.revoked_file` is unset. Grep finds no such token in `.github/` today. #243 item 246-1 (the CI lock step) must respect it.
  - New warnings only: an agent lane over the notice-signers file, an unreadable or linked file under `.github/`.
- **`literals.py`.** An unparsable link is now a `url` finding instead of exit 2. Not run by Decisya's CI.
- **`lock.py`, `bootstrap.py`, `capture.py`, `floors.py`, `labels.py`, `prereqs.py`.** Reviewed in G3; no further effect found. `project.json` accepts the optional `notice_signers_file`, `repository_url` and `key_change_serial` keys; Decisya sets none (enrollment is G3 S-7).
