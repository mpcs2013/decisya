## Question: can `decide_docker` return `None` after a load failure while Docker subcommands are present?

No, for every exception. `decide_docker` (`agent_boundaries.py:111-126`):
1. It runs the socket check first.
2. It returns `None` only when `docker_subcommands` is empty (`:117-119`).
3. Otherwise it loads the config with no `try` (`:121`), so `ConfigError`, `JSONDecodeError`, `RecursionError`, `MemoryError` and `TypeError` all propagate to `main()`, whose `except Exception` (`:213`) denies with `deny-error`.

A bare `docker` gives the subcommand `""`, so the list is non-empty and the config is loaded. When `main()` already holds a validated config, `decide_bash` passes `docker_patterns(config, agent)`, which validates again and can only raise (`:183`). The tests `test_malformed_docker_key`, `test_non_json_boundaries`, `test_loader_exceptions` and `test_no_fallback_constant` (`test_docker_config.py`) cover this.

The one gap is **non-termination**, which is not an exception: see G6-76-01 and G6-76-02. A hang reaches the harness timeout, and the harness then allows the call.
