## Not findings (checked)

- **Residual R-APIOPS** is stated at its real extent (`:316-328`). The uncapped operations are `read-identity-state`, `read-credentials` and `end-identity-sessions`. None of them changes who controls an account, and with Q-3's forced authentication, ending Keycloak sessions does not end Decisya sessions. Leaving them uncapped is consistent.
- **Ticket consumption on the published route.** The ADR-0016 amendment carries the ticket to the id host on the published realm route, while the provider prefix is refused there. So the consumption endpoint must lie outside the provider segment, as Keycloak's own action-token path does. If Ostium's design puts it inside, the flow fails closed. This is a design detail for R-1 and D-3's guards, not a security gap.
- **Decision 7's rotation text** (`:163`) names only the Api's secret file. D-8's scope (S333-06) adds the wrapper's file. This is covered.
- **The ADR-0016 amendment** adds no network, alias or published port. It keeps the admin paths on 8444 only, and keeps `cap_drop: [ALL]` as the basis for the single-address allow-list. It announces the changed behaviour and names its channels (the ADR, the release notes, review 17's update in D-6).
- **NFR-70 to NFR-74** match decisions 3, 5, 6, 7 and 9.
