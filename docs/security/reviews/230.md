## Narrowings made at G4 (G3 did not see them)

**N-01: an `out` argument is not an input of the call.** Sound. It hides no real leak.
- Where: `MethodRun.Opaque` only (`MethodRun.cs:1100-1103`, `1161-1174`). Bodies that the rule follows use their summaries and are untouched.
- Why it is safe:
  - When the method resolves, N-01 uses `ParameterDefinition.IsOut`. C# forbids a callee to read an `out` parameter before it assigns it, so the old content of the caller's variable cannot reach the receiver, the allocation or the other arguments.
  - The `out` variable still receives the union of every other input (`:1124-1139`), and the catalogue source of the call (`:1013-1023`). So `TryGetPayloadValue<string>("sub", out var s)` still taints `s`. `FrameworkReaders.JwtPayload` and the sync and async `LeakyLogoutLog` guards prove it.
- Residual (Info): when the method does not resolve, the rule falls back on the `Try…(…, out x)` naming convention for the last by-ref parameter. A `Try*` method whose last parameter is a `ref` input would lose only the flow from that variable into the receiver. The variable's own cell keeps its taint, because cells are unions. I know of no such BCL shape. Not a finding.

**N-02: the async builder's scheduling calls move no data.** Sound. It hides no real leak.
- Where: `MethodRun.cs:1083-1090` and `1152-1155`. It covers `Start`, `AwaitOnCompleted` and `AwaitUnsafeOnCompleted`, on a receiver whose type is in `System.Runtime.CompilerServices`, starts with `Async` and contains `MethodBuilder`.
- Why it is safe:
  - These calls only run or schedule `MoveNext`. They copy no user value.
  - Values move through `SetResult` into the builder (a hoisted field, kept in the shared store), through `get_Task` in the stub, and through `GetAwaiter`/`GetResult` and the hoisted awaiter fields. All of these keep their normal handling.
  - The red async guard (`LeakyLogoutLog.AsyncPath`) proves the end-to-end path: a subject read in a callee, returned through `SetResult`, awaited and logged, is still reported with its `JsonWebToken::TryGetPayloadValue` source.
  - Builders outside the match, such as the pooling builders and custom builders, are not narrowed, so the rule stays stricter there.
- It does not create G6-230-02. Before N-02, a stub's parameter did not reach `MoveNext` either: the shared field store keeps concrete sources only (`PersonalDataWorld.cs:224-239`), and the old `Opaque` handling of `Start` reached no sink.
