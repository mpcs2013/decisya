## Verdict

**PASS** (re-check, 2026-10-02; first pass PASS-WITH-NOTES). The Done-when holds: the grant step leaves `decisya_entitlements` with `INSERT` only on `audit.audit_records` and nothing for any other application role, inside one owner transaction that cannot widen on a re-run. `AuditBypassUsageTests` and the G4 integration suite pin it. All five MUSTs and S-1/S-2 are met. Both fix-now findings are fixed and pinned by red fixtures:

- **G6-24-01 (Medium), Fixed:** `RawAdoNetRule` is now an allow-list over the `System.Data.*` and `Npgsql.*` namespaces (the EF provider namespace `Npgsql.EntityFrameworkCore.*` is excluded). Only `DbTransaction.get_Connection`, `DbException.get_SqlState` and `PostgresException.get_ConstraintName` are allowed (`RawAdoNetRule.cs:25-48`).
- **G6-24-02 (Low), Fixed:** `ExplicitTransactionRule` allows members per type. The writer may use only `UseTransaction(Async)`, and `IDbContextTransaction` savepoint methods are banned for every type (`ExplicitTransactionRule.cs:81-170`).

Re-check run: `dotnet test --project tests/Decisya.ArchitectureTests`, 73/73 green, on the host. The backend-dev red run had 5 failing before the fix. One Low residual goes to backlog (G6-24-03).

## Checks requested by the orchestrator

- **The grant SQL:** role and schema come only from constants, and the revoke runs before the grant inside one transaction. Nothing widens on a re-run. See G4-24-01.
- **Deviation 1: `BannedSymbols.txt` unchanged.** Accepted. G3 asked for it only as IDE feedback, and the IL rule is the authority that CI enforces. It does not touch the Done-when, which is enforced by the database ACL.
- **Deviation 2: no separate `pg_maintain` revoke.** Accepted. `REVOKE ALL ON ALL TABLES` clears the table-level `MAINTAIN` privilege (Postgres 17+). `pg_maintain` membership can be granted only by a role admin, and the test asserts it is absent. In any case, MAINTAIN (VACUUM, ANALYZE, REINDEX, CLUSTER, LOCK) cannot update or delete a row, so it cannot weaken the Done-when.
- **Logging and storage:** no secret, raw `sub` or reason text is logged or stored beyond the intended `actor_user_id` column, which is `[Sensitive]`. The writer logs nothing, the actor-unknown log carries only the command name, and the handlers' success logs are unchanged from #23.
- **Dependencies:** no new package. `Microsoft.EntityFrameworkCore.Design` (PrivateAssets) and `Npgsql.EntityFrameworkCore.PostgreSQL` are already pinned and used by the other modules.
