Temporary-repository git runs use Git's own `sh`. |
| 2 | Is `find_bash()` sound? | Yes | On Windows the candidate is always `<ancestor of resolved git>\bin\bash.exe`. The WSL launcher sits at `<SystemRoot>\System32\bash.exe`, which never has that `...\bin\bash.exe` form. So it can only be reached through a junction or symlink, and `candidate.resolve().is_relative_to(<resolved SystemRoot>)` rejects that case. `is_relative_to` compares path components (a `C:\WindowsX` folder is not caught) and ignores case on `WindowsPath`. `Path(git).resolve()` follows scoop-style junctions to the real install folder. If `SystemRoot` is missing, the code falls back to `C:\Windows`. If `SystemRoot` has been changed, only the extra check is weakened: the form check above still excludes the launcher, and anyone who can change the environment or plant `bin\bash.exe` already runs as the user. If git sits under the Windows folder, every `bin\bash.exe` there is rejected, as `test_gitbash.py:35-39` proves. PATH's `bash` is never consulted on Windows (`test_gitbash.py:29-33`, plus the host test with System32 first on PATH, `:51-58`). |
| 3 | Is CI coverage on Linux unchanged? | Yes | When not on Windows, `find_bash` returns `which("bash")`, the same value as before. `ci.yml:282` runs `discover -s .claude/tests`, which puts the start folder on `sys.path`, so `from gitbash import BASH` resolves there and in `prepush.py:174-175`. `HostTests` adds a visible failure when git is present and bash is missing, which is stricter than the old silent skip. |
| 4 | Is the guard regex adequate? | Adequate, with easy misses (L-1) | The regex catches the two forms used before this change (`which("bash")` and `["bash", ...]`), and the G4 red check confirms it. See L-1 for the misses. |
| 5 | Is the pre-push hook or a CI gate weakened? | No | `prepush.py`, `ci.yml`, `gates.py` and `lint.py` are not in the diff. ## Findings

| Id | Severity | Status | Finding |
| --- | --- | --- | --- |
| L-1 | Low | fix-now | `NoBareBashLookupTests.LOOKUP` (`test_gitbash.py:70`) misses a tuple argv `("bash", ...)`, the name `"bash.exe"`, case variants (`"Bash"`), and `wsl`/`wsl.exe`. Each of these reaches the WSL launcher on Windows just as the forms it does catch. A few-line fix: `(?i)(which\(\|[\[(])\s*["'](bash\|wsl)(\.exe)?["']`, still built from parts so the file does not match itself. Grep of both test folders with this pattern finds no match today outside `gitbash.py`, which is excluded. The comma-separated form (`[..., "bash"]`) is left out because it would flag dict literals (`test_gitbash.py:32`, `test_agent_containment.py:192`). |

Accepted, no backlog item: the guard checks one line at a time and does not see a `shell=True` command string or a list split across lines. No such form exists today, and `gitbash.py` remains the single lookup point.
