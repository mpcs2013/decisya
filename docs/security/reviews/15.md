## Verdict

**PASS-WITH-NOTES.** No High is open. The structure matches G2 and G3's six design changes: one masking core for both sinks, providers cleared, OTLP scopes forced off, collections and framework types fail closed, a keyed and domain-separated hash, and fail closed outside Development.

One Medium is open. **M-1**: the `Uri` and value-shape rules (G4-15-16, 17) are applied only to top-level values and to members of objects the processor renders itself. Values that rule 2 (scalar collections) or rule 6 (fully known graphs) pass through reach the MEL-formatted message and `ToString()` without them. I recommend fixing it in this PR. If Marco defers it, it becomes a hard prerequisite for #18, #19 and #20, which are the first issues to handle bearer tokens.

Must be done in this PR: fix M-1, and add the G4-15-29 query-canary test (see "Rulings", 3). Everything else below can be accepted or followed up.

### 1. The G4/G5 host exception to ADR-0010

**Accepted for #15 as Marco's decision.** It is recorded with a reason in the manifest, and #56 tracks the standing rule.

Security effect: TB6 (sandbox → host) did not exist for this issue. Code written by the agents ran on the host immediately, during builds, tests and a real DCP start. ### 2. API divergences

- **Trait set per class: accepted.** `Decisya.AppHost.Tests` has one test class, and it carries the trait. A grep of `tests/` shows no other project uses `Category=AppHost`, so the T-27 mis-tagging risk is nil. If a new class is added without the trait, it runs in CI and fails loudly, because DCP is missing there; it is never silently skipped. Optional: if xunit.v3's `TraitAttribute` accepts an assembly target (`[assembly: Trait("Category", "AppHost")]`), prefer it and delete the per-class attribute. I haven't verified this against xunit.v3 4.0.1.
- **Obsolete `GetEnvironmentVariableValuesAsync`, CS0618 suppressed: accepted.** The suppression is a `#pragma` disable/restore pair around one line of test-only code, with its justification in a comment, so `-warnaserror` stays meaningful everywhere else. When Aspire removes the API, the build breaks loudly. At that point move to `ExecutionConfigurationBuilder`.
- **G4-15-06 asserts only that `OTEL_SERVICE_NAME` is present: accepted.** The security-relevant assertion is the presence of `OTEL_EXPORTER_OTLP_HEADERS`, which proves API-key auth to the OTLP receiver is configured, and that assertion is intact. The resolved service name is checked on Marco's dashboard. L-1 still applies to how the assertions are written.
- **`WatchAsync` takes the resource object: accepted.** No security impact.
