## Verdict (original review, superseded by the re-check above)

**BLOCK.** The G3 rule applies: G6 blocks when a "must" requirement has neither recorded evidence nor Marco's explicit acceptance nor a linked follow-up. That is the case here.

The implementation itself is sound, and most of it is well evidenced:

- read-only overlays;
- headless session model;
- SNI-checked proxy with the domain checks ordered before any IP rule;
- hardened containers;
- the build-output move;
- a fail-closed precheck.

The BLOCK comes from gaps in the recorded evidence plus one design regression. None of them needs a large change:

1. **Evidence missing for three "must" requirements.** The G3 threat model named a probe for each, and none is recorded in the manifest: G4-02 (`host-review.py` detection), G4-06 (precheck refusals) and G4-13 (user-level config can't be written or renamed). By reading the code I expect all three to pass. Recording the outputs (commands in [Unblock conditions](#unblock-conditions)) is enough.
2. **G4-11 is now only partially met (N-01, Medium).** Adding `platform.claude.com` also allows Claude Code's OAuth token endpoint (`https://platform.claude.com/v1/oauth/token`). A claude.ai subscription `/login` can therefore complete inside the sandbox. The Dockerfile, runbook and architecture note still say no login host is reachable. The fix is either a guard in `sandbox.py` or Marco's explicit acceptance, plus correcting the docs.
3. **G4-09 is only partially evidenced.** Some of the T-10 bypass probes are not recorded. The config itself is correct.

Once the unblock conditions are met, the expected verdict is **PASS-WITH-NOTES**. Every other open item is Low or Info and has a fix or a follow-up below.
