## Other checks (always-check list, the changed areas only)

- **BOLA.** The target tenant comes only from the route. Body members are `Disallow`, so a `tenantId` in the body is a 400. The caller can't choose a scope: only the attributed handler mints `TenantResolution.For`. `TenantExistence` takes a resolution, refuses non-`Tenant` before SQL, reads through the ordinary filter on `decisya_tenancy` and returns a `bool` (`TenantExistence.cs:17-26`). `AdminMintsNothingTests` pins that Admin mints nothing.
- **Order of the existence check.** It runs after validation and before `BeginTransactionAsync` in all three handlers. A false result logs the parsed target id (a GUID, not PII) and returns `tenant_not_found`. The C-4 fault-matrix rows (it throws, it returns false) are in `EntitlementsAdminPreconditionTests`.
- **Facade.** An unmapped `ErrorCategory` throws, so it becomes a generic 500 and never a success (`EntitlementAdminCommands.cs:46`). `EntitlementAdminResult.Failed` refuses `Succeeded` and undefined values.
- **Telemetry.** The counter tags are bounded sets (action and outcome). There is no tenant, user or reason tag (`AdminTelemetry.cs`).
- **Caching.** `UseNoStoreResponses` runs first and sets `no-store` in `OnStarting`, so it also applies to the 401 and the exception handler's 500.
- **JWT and cookies.** Unchanged (#20, #19).
