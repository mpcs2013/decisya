## Approved deviations (Marco, 2026-10-23; G3 M-1 e and the ADR-0021 item 4 Env rule)

Both are recorded as **approved deviations** from my G3 text. I do not block on either.

1. **Four distroless regular files with an exec bit:** `usr/lib/os-release`, `etc/ssl/certs/ca-certificates.crt`, `usr/share/doc/ca-certificates/copyright` and `etc/update-motd.d/10-uname`.
   - M-1 e has two aims: no executable that a command name can reach ahead of the BusyBox links, and no second toolbox from the base.
   - Three of the four are data files, and an exec bit on data is meaningless.
   - `10-uname` is a real upstream shell script. It runs only when it is named by path through a shell. Only `pam_motd` at login does that, and the image has no login. An attacker who can already invoke `sh` gains nothing from it. It calls `uname`, which is not a linked applet.
   - None of the four is in a `PATH` directory, so none can stand in for `nc`, `sh` or `wget`.
   - The allowance is exact. `check_files` compares the full sorted set (`caddy_image.py:673-676`), so an extra executable, a missing base file or a lost exec bit fails. Red tests exist (`test_caddy_image_script.py:75`, `:128-145`, `:227-234`). Setuid, setgid and file-capability checks are unchanged.
   - Condition: this rests on `PATH` keeping its standard value and the merged-usr links keeping their targets. F-1 turns that from an assumption into a check.
2. **`SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt` from the base.**
   - It names the file Go's `crypto/x509` already reads first on Linux, so the edge's trust store does not change.
   - The control that matters is the exact value: a value under the writable data volume would let a writer of that volume add roots. `BASE_ENV` requires exactly this key and value (`caddy_image.py:76`, `:611-613`), and red tests cover another value, a missing key and an extra key (`test_caddy_image_script.py:301-310`).
   - The bundle's content stays a base-trust residual (T188-06, S-8 backlog).

Both are written consistently in ADR-0021 item 4's amendment (`docs/adr/0021-self-built-caddy-edge-image.md:143-146`), the G2 note (`docs/architecture/self-built-caddy.md:86`) and the runbook (`docs/runbooks/caddy-image.md:17-19`), each with "re-checked on every base bump".

## Re-check

This is the one allowed re-check (2026-10-23, security-reviewer agent). Its only job was to confirm F-1. I used Read, Grep and Glob only. The test results and the real-image results below come from the orchestrator.

**F-1: Fixed.** The code does what the fix description asks:

The orchestrator reports that the locally built image's Env is exactly `PATH` and `SSL_CERT_FILE` with their pinned values, plus `XDG_CONFIG_HOME=/config` and `XDG_DATA_HOME=/data`. That confirms the pinned value is the base's real value.
- (b) Root links and `PATH` directories.
  - `ROOT_LINKS` maps `bin`, `sbin`, `lib` and `lib64` to their `usr/` counterparts (`:81-83`).
  - `merged_view` records each root entry under `@root/` with its kind and link target, and no longer drops it silently (`:659-664`).
  - `check_files` fails when a root entry is present but is not a symlink to exactly its target (`:694-697`).
  - It also fails when an existing `PATH_DIRS` entry is not a real directory (`:698-701`).
  - The orchestrator reports that `check_files` finds no problem on the real locally built image.
- (c) Red tests.
  - A changed or reordered `PATH`, an extra leading `/tmp` element, a dropped `/bin`, and a bare `/usr/bin` (`test_caddy_image_script.py:286-303`).
  - `bin` re-pointed to another target, `sbin` re-pointed, and `bin` as a real directory (`:267-277`).
  - `usr/local/bin` and `usr/bin` as symlinks (`:279-283`).
  - The real-shaped root (`bin`, `sbin`, `lib`, `lib64` links) passes (`:256-265`).
  - The constants are asserted (`:82-88`).
  - The orchestrator reports that all 208 caddy-image tests pass.
- Because of the fix, the condition on approved deviation 1 (`PATH` keeps its standard value and the merged-usr links keep their targets) is now a checked fact.
- The Dockerfile comment at `:52` now names `inspect`, which corrects the M-1 f note.

No new High or Medium. Two Low residuals in `merged_view`/`check_files` go to backlog #83, not to this PR (#84). Each can only come from a base digest bump, and Marco reviews every base bump.
