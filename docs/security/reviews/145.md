## Does the change weaken #120 T-22 / T120-02?

No. The checks are below.

| Question | Result | Evidence |
| --- | --- | --- |
| Is the diff limited to the two waits? | Yes | The hunks at `:57-58` and `:74-75` replace `WaitForAsync(() => !spans.IsEmpty, …)` with `WaitForAsync(() => spans.Any(s => s.Contains("/ping" or "/health", Ordinal)), …)` and add the comment line. Nothing else changed. `WaitForAsync` (`:88-95`, 5 s bound, 25 ms poll) and `CollectingProcessor` (`:97-104`) are unchanged. |
| Are any assertions removed or relaxed? | No | `:60` (`Contain … "/ping"`) and `:77` (`Contain … "/health"`) are context lines in the diff, so they are unchanged. Test 1 (`:19-42`) is untouched: the positive control `:40` and the negative assertion `:41` (no `/health` or `/alive` span from the management port) still stand. |
| Can the timeout path turn a failure into a pass? | No | `WaitForAsync` returns silently when the 5 s bound expires, and the caller's `Contain` assertion then runs and fails loudly. If the test token is cancelled, `Task.Delay` throws and the test fails. |
| Can the new condition end the wait early while the assertion would fail? | No | In tests 2 and 3 the wait predicate is the same as the assertion predicate. The queue only grows (there is no `Clear` or dequeue), so once the predicate is true the assertion is true. The old `!spans.IsEmpty` wait could end on the inner `"GET "` span before the server span ended. That race is what made the test flaky (CI output `{"GET ", "GET /ping /ping"}`). |
| Does a longer wait hide a negative case? | No | Tests 2 and 3 assert only that a span is present. A longer wait can only add spans, so it cannot help a missing-span bug pass. The one negative assertion (`:41`, test 1) is unchanged and still relies on the `/ping` positive control going last (`:33-38`), which already waited for the specific span. |
| Is the Host-header property still proven (test 2)? | Yes | If tracing were decided by the client-controlled Host header (`:52`, the management port), the `/ping` request on the application port would produce no server span. The wait would then time out and `:60` would fail. |
| Is "Development traces /health" still proven (test 3)? | Yes | If Development suppressed `/health`, no span would contain `/health`. The wait would then time out and `:77` would fail. |
