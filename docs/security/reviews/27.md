## B-01 fix review

The fix is correct and complete for the threat.
- **Inbound off in the BFF only.** `BffTracePropagator` returns null trace id, state and baggage. It is registered in the BFF's DI with `AddSingleton`, which overrides the hosting `TryAddSingleton(DistributedContextPropagator.Current)`. It is never assigned to `DistributedContextPropagator.Current`.
- **The OTel re-extraction is closed.** `UseInboundTraceRoots` sets the global text-map propagator to a plain `TraceContextPropagator`. OTel's AspNetCore instrumentation skips its own extraction when the propagator is exactly `TraceContextPropagator`, so it neither re-parents the span nor sets `Baggage.Current`. The red-first canary test proves the effect, not just the wiring.
- **Outbound still works.** YARP and the OIDC backchannel inject from the BFF's own root activity. The test asserts that the Api receives a valid `traceparent` with the BFF's trace id, and that the Keycloak token exchange carries a BFF-rooted trace. The header strip adds a second layer for YARP. The strip list (`traceparent`, `tracestate`, `baggage`, `Request-Id`, `Correlation-Context`) covers both the W3C and the legacy formats.
- **The Api is unaffected.** `UseInboundTraceRoots` is called only in `src/Decisya.Bff/Program.cs:19` (grep over `src/`). The method is opt-in and documented as process-wide. `InboundTraceRootsTests` pins that `AddServiceDefaults()` alone keeps the composite propagator, and it restores the global propagator in a non-parallel collection.
- No secret, token or PII is in the diff. No new package was added.
