## Rulings the orchestrator asked for

1. **G4-22-02's missing red fixture:** the MUST is **not fully met** without it. The fixture is not contrived, because `ConfigureConventions` is unsealed and runs a finalizing convention after the sealed `OnModelCreating`. It is **fix-now** (G6-22-02).
2. **S-1 to S-3:** **backlog #83**, none fix-now. The IL rule is authoritative and ignores suppressions (T-11 accepted). S-1 gives IDE feedback only and needs compile-fixture proofs. S-2 (T-13) needs a custom convention in reviewed module code. S-3 is Low. G6-22-02's fixture partly covers S-2's concern for the token, but not for the filter body.
3. **S-4:** no `src/` type has `[AllowCrossTenant]`. Only the green fixture uses the unnamed overload: **fix-now, one line** (G6-22-03).

- Skill text: the `isolation-test` template adds the detached Update/Remove case and "never read conflict values back". `module-scaffold` steps 6 and 7 name the constructor convention, `OnTenantModelCreating`, "never auto-stamped" and `ArchitectureScope` with `CrossTenantQueryRule`. - `PostgresFixture`: per-run password from `RandomNumberGenerator`, never printed. Image pinned by digest. Database name `t_` plus 32 hex characters, generated by the fixture and quoted in `CREATE DATABASE` (T-18 as designed). No secrets in the diff.
- `TenantIsolationException` and logs: fixed messages, type names only. `TenantResolution.ToString()` prints the tenant id, which the log schema already carries as `tenant_id`, so this is not a finding.
- Invariant 1: every mapped non-owned type must be `ITenantScoped`, and each root gets the named filter. Many-to-many property-bag join entities fail the model build, which is fail-closed. With G6-22-01 fixed, owned types are covered too.
