### The Identity failure (M-5)

`ProductionAdminMfaFlowTests.The_admin_acr_survives_refresh_of_the_access_token` failed once after 587 ms, with "The login did not finish within 8 steps" (`ProductionKeycloakStack.cs:591`). I accept it as a one-off, not a regression, for these reasons:

- **The changed packages are not on that path.** `LoginAsync` (`:504-592`) drives Keycloak's authorization-code flow with a plain `HttpClient`: PKCE, the login form, the OTP form. Neither the ASP.NET Core OIDC handler nor JwtBearer runs, and the BFF and Api are not involved. The Identity.Tests graph moved only `Microsoft.Extensions.DependencyInjection.Abstractions`. Keycloak, its Postgres, the realm and the test are unchanged.
- **The failure looks timing-dependent.** The loop runs out of steps without hitting the "Unrecognised page" or non-200 assertions. So Keycloak kept returning a recognised form, most plausibly the OTP form again. The test submits a TOTP computed on the spot right after it creates the user, so a code rejected at a 30-second window edge would fail this way. This is an inference: the log does not capture the last page.
- **The re-run and the rest of the suite passed.** The class passed 5 of 5 alone, and the other 149 Identity tests passed in the same run, including other sign-in and MFA flows that use the same `LoginAsync`.

CI's `build-test` runs the whole Identity suite on the 10.0.15 runtime and decides. If it fails there on the same test, stop and report to Marco. Do not re-run CI unchanged in the hope that it passes.
