## Re-check (2026-09-23)

All original findings verified fixed against code and tests, and the original evidence cases re-run against a fresh Release build:

- **M1:** `Allocate` arithmetic in `Int128`; 50M USD by `[int.MaxValue,1]`, 5bn VND and 100bn USD by `[1e6,1]` sum exactly; `long.MaxValue` JPY extremes sum exactly (after N1, `long.MinValue` minor units is rejected — see N8); out-of-range amounts throw `InvalidAllocationException`. 200,000 random cases (USD/JPY/BHD/CLF, negatives, ratios up to `int.MaxValue`): 0 wrong sums, every share within one minor unit, deterministic. Tests: `MoneyAllocationBoundaryTests.cs`.
- **M2:** `Money.MaxAllocationParts = 10_000`, checked before any array allocation.
- **M3:** `new Money(5m, default)` → `ArgumentException`; `default(Money).ToString()` does not throw; USD vs default → `CurrencyMismatchException`.
- **L1–L3:** messages sanitised and truncated; ASCII-letter-only codes (look-alikes, NBSP, fullwidth, Kelvin sign rejected); amount removed from the precision message.
- **L4, L5, I1:** fixed as recommended. I1: the coverage package licence still needs recording in the PR body.
