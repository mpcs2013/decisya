## Verdict

**PASS** after the re-check (5c9ded8, below). The original verdict was **PASS-WITH-NOTES**. The code meets every G3 design point. There are no High or Medium findings.
- Only the BFF's bearer is forwarded, and it is never sent to a non-https destination outside Development.
- An upstream 5xx body is replaced, and upstream `Set-Cookie` is dropped.
- Antiforgery runs on `/api`, and anonymous callers get 401.
- The refresh state machine covers B-1, D6, T-09 and S-3.
- Logout is server-side and fail-open, with S-4 in place.

Five Low findings are **fix-now**:
- F1: one G4-19-05 item (the logout failure counter) is missing from the code.
- F2 to F5: four G3-mandated tests are missing. The G4 evidence says "G4-19-01 to 04 are red, then green", but that is not true for F2 to F4.

Each fix takes a few lines in a file this PR already changes.

## Re-check (5c9ded8, 2026-09-28)

This is the one allowed re-check. It confirms F1 to F5 only, and nothing new at High or Medium was found in the changed lines.
- **F1.** `KeycloakTokenClient.EndSessionAsync` increments the counter at all three failure exits, with reason `discovery`, `status` or `exception`. `LogoutTests`' fail-open test asserts `reason=exception` through a `MeterListener`.
- **F2.** `Logout_during_refresh_is_not_undone` holds the refresh before it reaches Keycloak and removes the ticket. Then it releases the refresh, so Keycloak's success forces a write-back. The test asserts 401, the ticket still absent and nothing forwarded. Without `Condition.KeyExists`, `StringSet` would recreate the key, so this test checks the control itself.
- **F3.** The 503 theory covers a thrown error, a 500 and a `401 invalid_client`, each with exactly one call and the old tokens kept. `CountingBackchannelHandler` asserts an empty query on the refresh and end-session calls. A violation propagates, so the test fails loudly.
- **F4.** The no-header case runs for POST, PUT, PATCH and DELETE. `dev-bob`'s `af` cookie and header are sent with `dev-alice`'s session, and an anonymous-issued pair is used after login. Each gives 403 with nothing forwarded.
- **F5.** The log scan adds the 503 refresh flow and the failed end-session flow before the records are read.
- **Note.** The `AttachAccessTokenRequestTransform` comment now names the typed setter as the control.
- Orchestrator-reported results: build 0 warnings; unit lane 632 of 632; `Decisya.Bff.Tests` Integration 59 pass. These tests are new coverage of code that was already correct, so they have no red run. The manifest records this.
