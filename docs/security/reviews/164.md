**Ruling on `Api:Jwt:ResourceMetadataUrl` (S-164-03).** Decisya does not set the key. A grep over `src/`, `deploy/` and `.github/` finds it nowhere, and `deploy/compose/docker-compose.yaml:120-121` sets only `Api__Jwt__Authority` and `Api__Jwt__TrustedRootPath`. An environment variable `Api__Jwt__ResourceMetadataUrl` in a deployment *would* switch it on and change every 401 to `Bearer resource_metadata="<value>"`. This is not High or Medium, for four reasons:
- **Fail-closed and validated.** The value must be an absolute https URL of 1 to 2048 characters from the RFC 3986 set, with a host, no user info and no fragment. It cannot contain `"` or `\`, so no header injection is possible. An empty or invalid value stops start-up (XML `:163-173`, `:295-308`). The value is used verbatim and is never taken from the request, so a request cannot influence it.
- **Not an escalation.** Whoever can set the Api container's environment can already set `Api__Jwt__Authority`, which is worse.
- **No consumer.** The Api's only client is the BFF, which is server-side and ignores `WWW-Authenticate` parameters. RFC 9728 discovery matters only to OAuth clients that Decisya does not have.
- **Stricter when set.** While the URL is set, Ostium locks `OnChallenge`, `Challenge` and `ForwardChallenge`.

The residual is an unreviewed header change in production that `ChallengeResponseTests` would not see, because the test host does not read the deployment environment. A deploy check is worth having but is not needed for this PR. It goes to backlog as part of G3 B-4.
