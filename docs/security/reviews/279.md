## Extra look (Marco-approved), 758f184

Scope: only `fix(ci): give label-event runs their own concurrency group`. That is the `ci.yml` `concurrency.group` expression and `LabelTriggerTests.test_label_event_runs_neither_cancel_nor_are_cancelled`, read against the manifest section "PR #280 blocked after all checks were green". There is no new finding, and the verdict holds.

- **Required checks.** Concurrency decides only whether a run is cancelled. Every run, label-event runs included, executes the same jobs and steps on the same head commit.
  - The lane detection uses the merge commit's first parent for every `pull_request` action (`ci.yml:64`). A label run therefore selects the same lanes as the `opened` or `synchronize` run of that commit.
  - The only actor-dependent branches (the Dependabot exemptions) fail closed for a human labeller (F-4).
  - No job condition reads `github.event.action`, so nothing is skipped or weakened.
- **A stale run cannot decide a newer commit.** A label run of an older commit is no longer cancelled by a push. Its check runs still attach to that older head commit, and the newer commit's required checks come only from runs on the newer commit. A push still cancels the older commit's `opened`/`synchronize`/`reopened` run, since those share the per-PR group as before.
- **Injection.** The expression reads only `github.workflow`, `github.event_name`, `github.event.pull_request.number`, `github.ref`, `github.event.action` (a GitHub-defined enum) and `github.run_id` (numeric). It holds no user-controlled text, and a concurrency group is a key, never shell input.
- **Which events get a unique group.** Only `action == 'labeled'` or `'unlabeled'`. `push`, `schedule` and `workflow_dispatch` carry no `action`, so they get the empty suffix. `opened`, `synchronize` and `reopened` keep the shared per-PR group, so `cancel-in-progress` still applies to them.
- **The pin is exact.** It is an `assertEqual` over the whole two-line block (`group` and `cancel-in-progress: true`), so any edit to the expression, an added key or a removed `cancel-in-progress` fails it.
- **Notes (no finding).**
  - The new `ci.yml` comment "a newer push still cancels the run of the older commit" holds for the shared-group run only. A label run of the older commit runs to the end and spends runner minutes, but decides nothing for the new head. The comment could say so at a later edit.
  - Cost: a PR opened with N labels starts N+1 full, uncancelled runs. This is runner time only; the repository is public, so nothing is billed (manifest "Cost").
