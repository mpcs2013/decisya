# Security review (combined light tier): ADR-0019, Ostium identity packages (issue #147)

- Scope: `docs/adr/0019-ostium-identity-packages.md` (new), `docs/architecture/ostium-dependency.md` (new, G2), `docs/adr/0003-bff-session-pattern.md` (note), `docs/adr/README.md` (row), `docs/compliance/standards-register.md:14` (supplier row). `docs/ai/pipeline/147.md` was read only. I used Read, Grep and Glob only; the change set comes from the orchestrator's diff.
- Tier: light (Marco, 2026-10-15). This PR is a decision record and changes no code, hook or permission. The feed, the CI permission, `NuGet.config` and the lock files land in #164, which runs the full gates. So the light tier holds.
- Verdict: **PASS-WITH-NOTES.** There is no High. Two Mediums and two Lows are fix-now, and all four are wording in ADR-0019 or the register row. One re-check follows.

## Posture, in short

These parts are sound as recorded: source mapping `Ostium.*` to the private source only, exact pins, locked-mode restore, `GITHUB_TOKEN` with `packages: read` and no PAT in CI, the fail-closed rule "no deployment runs a block with an open High or Medium" (ADR :51), the plan to fix generic code once in Ostium, and an honest residual-risk statement. A High in frozen generic code before #164 blocks deployment until the switch. That is fail-closed, and I accept it.

There are two gaps:
- **The rule for security fixes has holes.** Some frozen code never moves to Ostium, and the rule gives it no fix path. It also gives switched blocks no fast path.
- **The evidence chain does not bind the hashes to the signature.** It is also defined for 0.1.1 only.

## Architect's open points (triage)

1. **Frozen app-owned code in `src/Decisya.Api/Authentication`.** The security part is fix-now in G6-147-01(a). Freezing that code until #164 is otherwise the architect's call; no action from security.
2. **Which fixture and which guard tests are frozen.** Fix-now in G6-147-03.
3. **Ordinary changes to unswitched blocks after the freeze.** No security action, because the security path is G6-147-01. Whether to allow ordinary changes is the architect's call (a drift risk, not a security one).
4. **The `ApiBoundaryTests` csproj package rule.** Belongs in #164 G2; the note already records it (note :57). No action here.
5. **Hash, tag and commit check on later bumps; SBOM location.** Fix-now in G6-147-02(c) and (d). The script or CI step that runs the check belongs in #164 G2/G3.
6. **Dependabot cooldown on Ostium security releases.** The rule is fix-now in G6-147-01(b). Whether to drop the cooldown for `Ostium.*` in `dependabot.yml` is #164 G3.
7. **Dependabot and Actions access with `GITHUB_TOKEN` alone.** Belongs in #164 G3. Verify it on a real Dependabot run and a real CI run before merge. If Dependabot needs a `registries:` entry with a stored token, take that back to Marco as an ADR-0019 amendment; do not add a PAT quietly. Two more points for that G3: never use `pull_request_target` to give fork PRs feed access, and keep the private source mapped to `Ostium.*` only, so it can serve no other ID.
8. **Sandbox restore, and the host credential.** Belongs in #164 G3. The workstation credential should be `read:packages` only, with an expiry, stored outside the repository (encrypted user-level NuGet config or the credential manager), never in a repository `NuGet.config`, and on the agents' never-read list. That list is a full-tier `.claude/` and CLAUDE.md change, so it needs its own issue. Also, ADR :18 "no PAT to rotate" is true only of CI. The loss of sandbox runs for identity issues is an ADR-0010/0011 consequence, for #164 G2.
9. **V6/V7 evidence lives in private Ostium.** Fix-now in G6-147-04. The fact that outsiders cannot inspect it is already accepted at :80.
10. **No test enforces the freeze before #164.** No action. ADR :85 states it, and G6-147-03 makes the review workable. The tooling freeze (#84) argues against a new guard.
