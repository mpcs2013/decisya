## DPIA seed review (exit-gate item 3)

The seed in `docs/PHASE-0.md` was read against the repository as it is today. The points below go into `docs/compliance/dpia.md` in Phase 1 (#240). None of them changes the Phase 0 position, because no real user's data is processed.

1. **Processing today.** Only synthetic accounts and seeded data exist. The go-live gate's C-02 check refuses any non-synthetic user (`docs/runbooks/go-live-gate.md`), and nothing is deployed: the deploy gate refuses on Keycloak's bundled guava (`docs/security/asvs-l2.md`, "Accepted residuals"). No data category is processed for a real data subject.
2. **Hosting and encryption.** The seed says "LUKS on the VPS". ADR-0016 moved Phase 0 to a home NAS with no internet exposure and kept the VPS as the go-live target. No document yet shows encryption at rest on the Phase 0 host. The DPIA must restate encryption per target.
3. **Object storage.** The seed names MinIO. ADR-0007 now says "S3-compatible; server chosen in the storage issue". The DPIA should name the server only after that issue.
4. **Retention not yet enforced.** Logs and traces have no retention period today, and the audit table keeps the raw actor id with no retention rule (`docs/security/threat-models/system-baseline.md`, "tenant_id in logs", items 2 and 3; C-04, held by #29). The seed's "audit log 12 months" is not implemented yet.
5. **A retention the seed does not list.** Keycloak's event store keeps usernames and client addresses for 90 days (NFR-45 residual R-1, NFR-46). This belongs in the retention schedule.
6. **Erasure.** The seed says the audit log keeps a pseudonymised record. The audit table stores the raw `sub`, and the future erasure job must decide whether to pseudonymise or to keep it on a legal-obligation basis (system-baseline.md, item 3). The source tree has no tenant-deletion job yet.
7. **Breach procedure.** The seed names a runbook with a 72-hour checklist. No such runbook exists under `docs/runbooks/`.
8. **Sub-processors.** Today none of them receives personal data from data subjects. GitHub hosts code, CI and the release images, and holds no user data. The hosted LLM provider has no role until Phase 5.
9. **Open question from the seed.** Whether EU data residency is a stated commitment is still open for Phase 1.

Verdict on the seed: reviewed. It remains a fair Phase 0 outline. Points 2 to 7 must be fixed in `docs/compliance/dpia.md` before the first real user.
