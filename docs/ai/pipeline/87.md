## G7 PR body draft

**Fix BFF sign-in in local development: connect to Redis on 127.0.0.1**

Closes #87

**Problem:** after #18, signing in through the BFF in the running AppHost failed with a 500. Aspire gives the BFF a `localhost:<port>` Redis connection string. On Windows, `localhost` resolves to IPv6 `::1` first, but the Redis container listens on the IPv4 loopback only, so the connection took about 2 s (measured: 2058 ms against 31 ms for `127.0.0.1`). That exceeded the BFF's 1 s fail-closed connect timeout, so storing the session ticket failed. The integration tests connect by IP, which is why they passed.

**Fix:** `RedisRegistration` rewrites a `localhost` endpoint to `127.0.0.1` with the same port before connecting. The fail-closed timeouts, the loopback-only binding and the rest of the Redis options are unchanged. Only a host that is exactly `localhost` is affected, so a deployed Redis addressed by name is not.
