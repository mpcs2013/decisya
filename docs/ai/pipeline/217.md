## G7 PR body draft

### Summary

On Windows, `shutil.which("bash")` returns `C:\WINDOWS\system32\bash.EXE`, the WSL launcher, whenever Git's `bin` folder is not on PATH (only `Git\cmd` is). On 2026-10-30 a local `.claude` suite run then started hundreds of commands in the WSL Ubuntu distribution, opened many empty VS Code windows and dropped the Claude session. Closing the windows lost other running work. The pre-push hook (`prepush.py:174`) runs the same suite on every push, so a terminal without Git's `bin` folder would hit it too.

- New `.claude/tests/gitbash.py`: one `find_bash()`. On Windows it walks up from the resolved `git` executable to `bin\bash.exe` and rejects any path under the resolved Windows folder. Elsewhere (CI on Linux) it uses the bash on PATH, as before.
- `test_gates.py`, `test_ci_fullstack.py`, `test_ci_changes.py`, `test_realm_guard_trigger.py`, `test_ci_gates_fail_closed.py` and `test_release.py` take `BASH` from it (`test_release.py`'s own copy removed; two unused `import shutil` removed).
- New `.claude/tests/test_gitbash.py` (8 tests):
  - the lookup rules, including this host with System32 first on PATH;
  - one visible failure when Git Bash is missing (the bash-based tests skip, never fall back);
  - a guard against a bare `bash`/`wsl` lookup (`.exe`, any case, list or tuple) in `.claude/tests` and `deploy/tests`, with a test of the pattern itself (G6 L-1).
- `prepush.py`, `ci.yml` and the gate machinery are unchanged.

Norma is asked for the same prevention in its package (exchange D-007; Norma answers it in 0.2.1).
