## G7 PR body draft

**API: validate Keycloak access tokens and protect every endpoint (0.08)**

Closes #20

**Summary** (ADR-0002, ADR-0003; closes the #20 boundary #19 left):
- **JWT bearer validation in `Decisya.Api`.**
  - Algorithms RS256 and ES256 only; audience `decisya-api`; issuer pinned to the configured Keycloak realm; clock skew 60 s (NFR-27).
  - Keys from Keycloak's JWKS.
  - Tokens whose `typ` isn't `Bearer` are refused at authentication, so an ID token can never pass, even if the audience rule changes.
  - `alg=none`, HS256 (including HS256 keyed with the realm's public key), and expired, wrong-audience and wrong-issuer tokens all get a bare 401, with an empty body and a plain `WWW-Authenticate: Bearer`.
  - A Keycloak metadata outage also gives a bare 401.
- **Deny by default.** A fallback policy requires an authenticated user with `sub` on every endpoint. Only `/health` and `/alive` are anonymous, and they exist only in Development.
- **`GET /api/whoami`** returns the caller's `userId` and `tenantId` from token claims only. A client-supplied `X-Tenant-Id` or user header is ignored. Malformed identity claims give 403.
- **Generic errors** (ProblemDetails) in every environment; no forwarded headers are trusted.
- **Startup guards:** outside Development the app refuses to start on an http authority or relaxed metadata. The error names the key, never the value.
- **AppHost:** the API gets the Keycloak authority (the same expression as the BFF, so the issuer matches `iss`) and no secret.
- **CI:** `Decisya.Api.Tests` joins the Integration step.

Docs: docs/GETTING-STARTED.md, docs/requirements/nfr.md

**Packages:** none new. `Microsoft.AspNetCore.Authentication.JwtBearer`, `Testcontainers.Keycloak` and `NodaTime` were already pinned in `Directory.Packages.props`. `dotnet list package --vulnerable --include-transitive` finds nothing for `Decisya.Api`.

**Security:**
- G3: `docs/security/threat-models/api-jwt-validation.md`, PASS-WITH-NOTES; five Highs, each mitigated here.
