## G4 evidence

**identity-dev** (`src/Decisya.Bff/**`, `tests/Decisya.Bff.Tests/**`, realm and realm tests), following G1 to G3:
- `Decisya.Bff` is a new host, referencing only ServiceDefaults:
  - endpoints `GET /bff/login` (local `returnUrl` only), `GET /bff/me`, `POST /bff/logout` (session plus antiforgery), and `POST /bff/backchannel-logout`;
  - a cookie handler and an OIDC handler (code flow with PKCE, `ResponseMode=query`);
  - `RedisTicketStore` with Data Protection, the purpose bound to the session key;
  - fail-closed Redis handling (1 s timeouts);
  - options validation that rejects the Development relaxations outside Development;
  - `SessionFixationGuard`;
  - an antiforgery endpoint filter, with only the back-channel endpoint opted out.
- Realm: `backchannel.logout.url`, the `realm-roles-id-token` mapper, and front-channel logout off (S-7), with realm tests added.
- G3 MUSTs G4-18-01 to 05, each red, then green. The red phase caught real bugs:
  - `LogoutTokenValidator` could never read the `events` claim, because of its deserialisation type;
  - it rejected tokens without `exp`, because the library still validated lifetime;
  - the session-fixation test harness was double-sending cookies.
- SHOULDs:
  - taken: S-1, S-2, S-3, S-4, S-5 and S-7;
  - not taken: S-6, the Keycloak trust of the host dev certificate for the back-channel call. It is a manual host check for Marco (below).
- A test-infrastructure fix: `EagerConfigurationGuard`, because Aspire's Redis client reads its connection string before the test factory's overrides apply. Test parallelism is off in `Decisya.Bff.Tests`, since the tests share one Keycloak.
