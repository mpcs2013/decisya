## G7 PR body draft

### Summary
The review-required check (`.claude/scripts/gates.py`, run by the Pipeline gates step in `ci.yml`) makes G3 and G6 mandatory when a change touches a hook, an agent lane, the permissions or a workflow. Four gaps let such a change skip them:
- **Renames:** the base diff listed only the new path. A hook moved out of `.claude/hooks/` looked like a docs change.
- **Non-ASCII paths:** git quoted them, so the quoted path no longer matched the rule.
- **Leading-zero branches:** `issue/0148-x` gave the number `0148`, the branch check in `gates.py` then failed, and it printed only a WARN and skipped the rule.
- **A failed base diff** (no `origin/main`, a shallow checkout) returned an empty list, and the check passed. On the host, the first `git status` path also lost a character.

The changes:
- `changed_files()` uses `git diff --name-only --no-renames -z` against `origin/main...HEAD` and the working tree, plus `git ls-files -z --others --exclude-standard`. It decodes as UTF-8 and splits on NUL without stripping, as `prepush.py` does, and the `git status --porcelain` parsing is removed. If any listing call fails, it returns None and the check fails.
- In CI (`GITHUB_ACTIONS=true`) a branch mismatch, including a detached `HEAD`, is a FAIL. On the host it stays a WARN.
- The gate step accepts only `issue/<n>-<slug>`, where `n` has no leading zero and the slug is lowercase: `^issue/([1-9][0-9]*)-[a-z0-9][a-z0-9-]*$`.
- From the G3 notes: the rule's regex matches newline and case-variant paths (`DOTALL | IGNORECASE`), and printed paths have control characters escaped.

**Merge order:** this changes `ci.yml`, so the image-scan lane runs on this PR and stays red until #142 lands. The PR opens as a draft and merges after #142.
