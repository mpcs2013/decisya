## G7 PR body draft

**BFF: forward /api to the API with server-side tokens and transparent refresh (0.07)**

Closes #19

**Summary** (ADR-0003; builds on #18):
- **Forwarding.** YARP in `Decisya.Bff` forwards `/api/**` to `https://decisya-api`, found through Aspire service discovery.
  - The route table is code-only; there is no configuration route.
  - The browser's cookies, its `Authorization` header and the antiforgery headers are stripped, and the user's access token is attached server-side. The destination must be https outside Development.
  - An upstream `Set-Cookie` is dropped, and upstream 5xx bodies are replaced with a generic error, so an API exception page can't echo the bearer back to the browser. WebSocket and upgrade requests are rejected.
- **Transparent refresh (the Done-when).** An access token within 30 s of expiry is refreshed before forwarding, under a per-session Redis lock: 10 concurrent requests make exactly one Keycloak call. The refreshed ticket is written back only if the session still exists, so a logout during a refresh stays a logout.
  - `invalid_grant` ends the session and the caller gets 401. Other Keycloak failures return 503 and keep the session.
- **Logout (B-2)** now also ends the Keycloak SSO session server-side. A failure there is logged, counted (`decisya.bff.keycloak_logout.failures`) and doesn't block the local logout.
- **Antiforgery (B-3)** covers every state-changing `/api` method. An anonymous caller gets 401 first, never a redirect.
- **AppHost:** `decisya-api` runs on https, and `decisya-bff` references it.
- **Tests:** the Done-when refresh, the concurrency bound, B-1 to B-3, header stripping, the leak scans (responses and all logs at Debug), the https destination check, and the race and failure paths.

Docs: docs/requirements/nfr.md

**Packages:**
