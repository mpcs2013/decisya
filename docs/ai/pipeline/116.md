## G7 PR body draft

**Make the BFF trace-context isolation tests wait for the server activity**

Closes #116

**Summary.** `TraceContextIsolationTests` failed at random in `build-test` (2 of about 30 runs, both on unrelated Dependabot PRs). The test recorded the BFF's request activity in `ActivityStopped`, and the in-process test server can hand the client its response before the hosting layer stops that activity. The test now waits for the activities it checks:
- A new `ServerActivityCapture.WaitForAsync` polls every 10 ms, bounded at 5 s, and honours the test's cancellation token. On timeout it returns the snapshot anyway, so the assertions still fail and report what is missing.
- Test 1 waits for the BFF's https activity and the Api double's activity on the same trace. Test 2 waits for the login callback's activity, whose trace the Keycloak token exchange carries.
- Every assertion is unchanged, so the #27 B-01 guard still holds: the BFF never adopts a browser-chosen trace id, tracestate or baggage, and never forwards them.
- No production code change.
