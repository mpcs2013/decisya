## G7 PR body draft

### Summary
The production identity for the deployable stack (#120). Phase 0 has synthetic users only (ADR-0016).

- **Production realm** (`deploy/keycloak/production/realm-decisya.json`, C-03):
  - no seeded users; `sslRequired: all`;
  - plain `${NAME}` placeholders filled by the hardened `entrypoint-stack.sh`. It validates the host, port 8443 and the client secret, refuses pre-set values, and runs `kc.sh start --import-realm` itself.
  - The stack mounts exactly this one realm file and the password list, read-only. The #120 "no realm mount" guard becomes "exactly this file".
  - A parity test against the dev realm allows only differences P1 to P8.
  - The dev realm and the dev AppHost are unchanged.
- **Admin MFA** (#25 C-5):
  - a step-up flow gives `platform-admin` holders `acr` "2" through TOTP; the BFF always sends `acr_values=2`;
  - `/api/admin` requires exactly one `acr` "2" claim (policy `Api.AdminMfa`, a coverage test on every admin route);
  - `Authentication:RequireAdminMfa` is true by default and fails closed outside Development. The dev AppHost turns it off in run mode only.
- **C-02 (Marco's decisions Q1 to Q8):**
  - admin MFA and Keycloak's native password checks are enforced now, including the common-password list;
  - tenant-user MFA is configured but off;
  - breached and context-specific checks are designed only.
  - The trigger is the first non-synthetic user. It is tracked by `docs/runbooks/go-live-gate.md` and by `synthetic=true` on every user, checked by `stackctl verify` through the read-only `identity-check.sql`. That check also fails on any master-realm user or service account without OTP once the bootstrap secret is retired.
  - `stackctl realm rebuild --confirm` exists only while every user is synthetic.
- **Authentication events (C-10):**
  - Keycloak login and admin events are stored for 90 days, admin events without details, with no stdout listener;
  - the BFF logs `auth.signin.succeeded`, `auth.signin.failed` and `auth.signout`;
  - the Api logs `auth.token.rejected`, including the previously silent `bad_type`, and `auth.admin.mfa_required`;
  - every event has fixed text and closed reason lists, and the hashed user id comes only from log enrichment.
- **Fixed along the way:**
  - The OIDC handler logged the provider's `error_description` and exception text at Error level. That category is now set to `None` in the BFF, with a test.
  - The BFF principal dropped `acr`.
  - The RealmGuard working-tree scan now skips Python bytecode caches (G6 ruling).
- **Also:** a one-line wording fix in `docs/ai/pipeline/135.md` (the ruleset change shipped in the same commit, `354eb8b`).
