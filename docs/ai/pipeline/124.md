**ADR-0016: hosting for Phase 0 on the home NAS (0.17-pre)**

Closes #124

**Summary.** Phase 0 runs on Marco's Synology DS918+ NAS as a private staging box. The rented EU VPS (the first draft) is the go-live target and the fallback when a trigger fires. ADR-0016 is **Accepted**; Marco's decisions are from 2026-10-04 and 2026-10-05.
- **Host and access:**
  - x86-64-v2 CPU, so no UBI 10 / RHEL 10 bases (trigger F6);
  - LAN only, with no VPN and no port-forward;
  - **QuickConnect disabled**;
  - Caddy published as `<LAN 1 address>:8443:8443`.
- **Names and TLS:**
  - `nas.home.arpa` for DSM; `app.p0.home.arpa` and `id.p0.home.arpa` for Decisya.
  - **Caddy's internal CA**, because `.home.arpa` (RFC 8375) cannot get public certificates. So the stock, digest-pinned Caddy image, with no domain and no DNS token.
  - The root is trusted only in a dedicated Phase 0 Firefox profile and Playwright, and mounted read-only into the BFF and Api. It is regenerated at the Phase 0 exit, on the move to the VPS, or on suspected compromise.
- **Isolation (R9, MUSTs for #120):**
  - a dedicated folder and user;
  - no Docker socket, personal shares or privileged containers;
  - 2FA on every DSM account;
  - SSH key-only, LAN only, and re-checked after every DSM update;
  - kept apart from the other project that uses the NAS as a backup target.
- **Back channel:** a dedicated network with a fixed subnet; Keycloak's `/admin/*` and `/realms/master/*` reachable from Marco's workstation only, and port 9000 never routed.
- **Size and fallback:**
  - about 3.5 GB of container limits;
  - fallback triggers F1 to F6 (Keycloak start, login and API latency, memory and swap growth per run, end of DSM security updates, CPU or isolation not met).
- **Backups:** an encrypted Hyper Backup of the stack's dumps and key ring to an EU S3 bucket, provider chosen in #30.
- **Downstream:** each of #119, #120, #121, #122, #29 and #30 has a comment with the decisions that apply to it (the Done-when).
- **Local-only notes:** `ops.local/` (Marco's home network and NAS hand-over) is ignored by git and the image build context, pinned by a new test.
- **#119 records, also in this PR:** the `v0.1.0` release evidence in `docs/ai/pipeline/119.md`; ADR-0017 marked Accepted; the `CHANGELOG.md` bootstrap placeholder turned into a "Before 0.1.0" note.
