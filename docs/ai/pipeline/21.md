## G7 PR body draft

**Modules.Tenancy: tenants, memberships and a least-privilege database role (0.09)**

Closes #21

**Summary.** This PR adds the first business module on the tenant foundation from #22. It also makes the API require that each caller has a membership in its tenant.
- **`Decisya.Modules.Tenancy` and `.Contracts`** (schema `tenancy`):
  - `Tenant`, `Membership` (unique on tenant plus user) and `TenantRole` (Owner; Member is defined but unused);
  - `TenancyDbContext` on `TenantDbContext`, and the migration `AddTenantsAndMemberships`;
  - `GET /api/tenancy/me` and `GET /api/tenancy/members` (policy `Tenancy.Owner`), both `Cache-Control: no-store`.
- **First sign-in:** on a caller's first request, if their `tenant_id` has no tenant yet, the API creates the tenant and makes the caller its Owner.
  - It never joins an existing tenant; such a caller gets 403.
  - This is idempotent under concurrency: it checks the tenant first and handles 23505 only on the two named constraints, with one re-read.
  - It never runs inside a transaction.
- **API pipeline:**
  - order: exception handler → authentication → caller context → routing → tenancy membership → authorization;
  - `RequestCaller`, one scoped instance for `ICurrentTenant` and `ICurrentCaller`, set once;
  - an invalid identity or tenant claim gets 403 before any database access;
  - only `/health` and `/alive` are anonymous, and only `/api/whoami` skips the membership check;
  - `ValidateScopes` and `ValidateOnBuild` in every environment;
  - a concurrency conflict returns 404 with only `status`, `title`, `type` and `traceId`.
- **`Decisya.Infrastructure.Migrator`:** a new project, and the only EF design-time startup project.
  - It applies the migrations and creates the `decisya_tenancy` role idempotently, with DML on its own tables only: no DDL, no TEMP, no SET ROLE, no migration history.
  - It sets the password from a client-side SCRAM-SHA-256 verifier, so the plaintext never reaches SQL or server logs.
  - It rejects any password that isn't alphanumeric with at least 32 characters.
- **AppHost:**
  - a secret `tenancy-db-password` and the database `decisya`;
  - `decisya-migrator` gets the owner connection;
  - `decisya-api` gets only `ConnectionStrings__tenancy` (role `decisya_tenancy`) and waits for the migrator to complete.
- **Two 403 shapes (G3 S-2):**
  - A missing identity, an invalid tenant claim or a refused membership returns a generic ProblemDetails with `type`, `title`, `status` and `traceId`.
  - The `Tenancy.Owner` policy returns an empty body.
  - Neither carries a reason, a claim or a `sub`.
- **Tests:**
  - two-tenant isolation (the Done-when);
  - N=16 race tests for first sign-in;
  - migrator privilege tests (every forbidden operation fails with 42501) and a SCRAM round trip;
  - pipeline tests: 2×25 interleaved requests from two tenants, and the anonymous and skip sets pinned;
  - an HTTP round trip for the conflict 404;
  - static and live AppHost wiring tests.
- **Tooling:** the `ef-migration` skill and `prereqs.py` now name `src/Decisya.Infrastructure.Migrator` as the startup project. CI runs the two new Integration test projects.
