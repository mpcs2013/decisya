feat(logging): keep pii out of log arguments (c-12)

**Summary**

Closes register finding C-12 (Medium) before the first Ledger feature (D-012 point 2).

- **`PersonalDataLogRule`** in `Decisya.ArchitectureTests` fails a test when a log call in `src` passes catalogued personal data without masking.
  - It is an IL taint check (Mono.Cecil, already pinned).
  - It covers `ILogger` calls, `[LoggerMessage]` methods, scopes, `LoggerMessage.Define*`, string interpolation, exception messages, and `Console`/`Debug`/`Trace` writes.
  - It judges the value's source, not the placeholder name, and tracks per field through records, factories and async returns. A whole Decisya object is a finding unless its type, or the member holding the data, carries `[Sensitive]`.
  - It reports file and line, with repo-relative paths and no literal values.
- **The personal-data catalogue** `docs/security/personal-data-catalogue.json` (version 2) is reviewed by G3/G6 and outside the implementer lanes. Its seven categories are user id, contact, name, account number, free text, AI prompt/output and secret material, plus claim and token readers.
- **`[PersonalDataLogReviewed(category, justification)]`** is the only suppression. Each use must match a catalogue `suppressions` entry; secret material is never suppressible. **The suppression list is empty at merge.**
- **`[Sensitive]`:**
  - added to `Membership.UserId`;
  - added to `MemberDto.UserId`, with a `PrintMembers` override so `ToString()` prints only `Role`;
  - `AuditRecord.ActorUserId` already carried it.

  Each has a canary masking test. No API JSON, column or migration changed, and tests prove it.
- **Rule precision:** two engine narrowings were made in G4 and accepted at G6. N-01: an `out` argument is not a call input. N-02: the async builder's scheduling calls move no data. Guard fixtures prove a real `Subject` leak is still reported on both the sync and the async path.
