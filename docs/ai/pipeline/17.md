**Findings made with Docker, and their fixes:**
1. **Keycloak 26.7.4 does not substitute `${env.X}` at realm import.**
   - Marco's live login as dev-alice with the literal text `${env.DECISYA_DEV_USER_PASSWORD}` succeeded. `RealmConfigurationTests.The_stored_client_secret_equals_the_environment_value_the_placeholder_resolved_to` failed, as G3's T-01 guard intended.
   - The realm now uses Keycloak's documented `${X}` form.
   - `PlaceholderSubstitutionRegressionTests` requires Keycloak's "Invalid username or password." response for the `${X}` literal, the `${env.X}` literal and an empty password.
2. **Login tests returned 400 because .NET's `CookieContainer` drops Keycloak's `Secure` cookies over http.** The 400 body said "Restart login cookie not found"; `AUTH_SESSION_ID`, `KC_RESTART` and `KC_AUTH_SESSION_HASH` are `Secure; SameSite=None`.
   - Fixed with the test-only `SecureCookieRelayHandler`.
   - backend-dev's interim theory, that Keycloak substitutes credentials differently on a first start, was withdrawn.
3. **The restart test hung:** Testcontainers.Keycloak's wait strategy waits for a log line that isn't printed on a restart. Fixed with a bounded restart and a readiness poll.
4. **The dev issuer is `https://localhost:8080/realms/decisya`:** Aspire 13.5.4 terminates HTTPS for the container when the dev certificate is trusted (container port 8443, host port 8080). The G2 note and GETTING-STARTED are corrected; tests assert only the `/realms/decisya` suffix.
5. **The volume reset failed with "volume is in use":** the stopped AppHost containers still held the volume. GETTING-STARTED's reset now removes them first.

**Dev-volume incident and container lifetime (2026-09-26/27).**
- The first AppHost test run started while Marco's AppHost containers were still up. They were orphans from a hard stop (label `persistent=false`, no dcp process left).
- Two Postgres servers then wrote `decisya-postgres-data`, and the volume was corrupted: `PANIC: could not locate a valid checkpoint record at 0/2244B58`. Marco reset it and re-verified the dev-alice login.
- Fix (commit d542bf5, Marco's decision):
  - Postgres and Keycloak run persistent with fixed names (`WithLifetime(ContainerLifetime.Persistent)`, `WithContainerName("decisya-postgres"/"decisya-keycloak")`). The `WithPersistentLifetime()` shorthand raises `ASPIREPERSISTENCE001` and is not used.
  - The AppHost tests pass `--AppHost:UseEphemeralContainers=true --Postgres:DataVolumeName=decisya-apphosttests-<guid>`, remove that volume afterwards, refuse to remove `decisya-postgres-data`, and bound their waits at 3 minutes.
  - A static test guards the persistent and override wiring.
  - Before the first persistent start, the two orphans were stopped cleanly (Postgres logged `database system is shut down`).
