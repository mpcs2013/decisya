## G7 PR body draft

Keycloak's admin paths move to their own published port (8444), and the published ingress drops the Caddy source-address allow-lists that cannot work behind the NAS runtime's userland proxy. The NAS per-interface firewall becomes the documented control (ADR-0016 R9.6/R9.8 amendment), and #132's runbook carries the firewall rules, the source-address measurement and the refusal checks.

- **Caddy:** a second site on the id host, port 8444, admits only the admin console paths; the 8443 id site returns 403 for them before any admitting route, and refuses paths still holding an encoded dot, slash or backslash after one decode. Every route reachable from outside keeps a `not remote_ip` over the internal networks; back-channel routes are unchanged.
- **Compose:** a required `DECISYA_ADMIN_PORT` (8444); both ports are published on the bind address only and fail closed. `DECISYA_LAN_SUBNET` and `DECISYA_WORKSTATION_ADDRESS` are retired and refused by `check`. Keycloak gets `KC_HOSTNAME_ADMIN` on the admin port (AppHost model, regenerated `docker-compose.yaml`).
- **Guards:** two listeners; a `PUBLISHED_ROUTES` table naming the NAS firewall rule per published route; no admin path reachable on 8443 (case and encoding variants); refused risky path patterns and matchers; a static runbook check; red cases for each rule.
- **Master realm:** brute-force detection (no permanent lockout) is a new identity-check row, checked by `verify` once the bootstrap secret is retired. An Integration test exercises the runbook's own `kcadm.sh` command.

**Rollback:** revert this PR. The merge deploys nothing. On a stack already brought up with this change, restore the two retired keys and drop `DECISYA_ADMIN_PORT` in the stack's environment file, remove the NAS firewall rule for the admin port, and redeploy. Master-realm brute-force detection may stay on.
