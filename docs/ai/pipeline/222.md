## G7 PR body draft

### Summary

Implements ADR-0022 items 1 and 4 and its transition (accepted 2026-10-30, #216). A pull request's `image-scan` now fails only on what the pull request introduces, and the strict gate moves to where risk starts: the deploy.

- **PR gate** (`.github/scripts/image_scan.py`, `ci.yml`). The script selects its mode from the merge commit, and every doubt gives the full scan:
  - **delta:** only the images whose pin changed, scanned at base and head; only findings new at the head fail;
  - **gate-change:** the scan code, the scanner pin or `ci.yml` changed, so every image is scanned at base and head, with the base on `main`'s own code from a second checkout of the same pinned action. R-1 applies: with the same scanner and reference, a raw base match missing at the head fails. An unusable base fails;
  - **validator:** only `exceptions.json` changed, so nothing is scanned;
  - **full:** push, schedule, an unknown base, or an unclassified lane path.

  The finding key is exact (image, package, type, id), and a severity rise counts as new. Every call into the base module fails closed, `SystemExit` included. The scanner pin, `scan_argv`, `SCAN_ENV`, `PLATFORM` and the item-4 code are unchanged. `image-scan` keeps no job-level `if`. The `changes` job's diff gains `--no-renames`.
- **Deploy gate** (`deploy/compose/stackctl.py`, `stackguards.py`). A new `stackctl scan` writes a result file beside the stack folder (0600, atomic, owner-checked). It binds the scan time, the scanner, the database build, the hashes of `exceptions.json` and `image_scan.py`, and all eight image references (`api`, `bff` and `migrator` strict).
  - `up`, `check`, `realm rebuild` and `keyring prepare` refuse, before any Docker call, unless that result is at most 24 hours old, matches, and is clean. `realm rebuild` and `keyring prepare` also check the assembled stack.
  - There is no override.
  - `keyring reset` stays ungated for incident use but can no longer create containers.
- **Gate machinery:** `gates.py` makes `stackctl.py`, `stackguards.py` and `test_stackctl.py` review-required.
- **Docs:**
  - the two runbooks (the scan step, the four modes, the R-2 steps, and that a re-run reuses the event, so the remedy is a new push or "Update branch");
  - the ADR-0021 pointer line;
  - the ADR-0022 R-1 clarification (approved by Marco 2026-10-30).

**Consequence:** while Keycloak's bundled guava (GHSA-xxph-c9ww-hj94) has no fixed release, `stackctl check` and `up` refuse. This is intended, nothing is deployed, and there is no bypass. After this merges, ADR-0015's PR-path rules end and the paused chain #213 → #214 → #215 resumes. Drift tracking is #223.
