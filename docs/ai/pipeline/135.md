## G7 PR body draft

### Summary
`roster.py` leaves out skills that Git doesn't track, so a developer's git-ignored local skill no longer makes `roster.py --check` (the claude-lint pre-commit and pre-push hook) report `docs/ai/README.md` as stale. Until now, every commit and push needed the local skill folder moved out of the repository.

- **How:** `roster.py` reads `.git/index` itself, with the standard library only. NFR-19 still holds: no subprocess, no network, no environment.
  - It supports index versions 2 to 4.
  - The index only filters the existing skills glob.
  - Any doubt falls back to today's behaviour, every skill on disk: no `.git`, an unreadable, truncated, oversized (over 64 MiB) or checksum-failing index, an unknown version, a SHA-256 repository, or a split or sparse index.
  - Agents are not filtered. Lint and the hooks still find every skill on disk, so a local skill is still linted.
- **CI** runs on a clean checkout, where every skill is tracked, so the CI result is unchanged.
- **Also in this PR** (shipped in the same commit as the roster fix, `354eb8b`; it was planned as a separate `chore(ci)` commit; corrected in #121): the ruleset file records `deploy-guards` (#120).
  - It adds the `deploy-guards` context to `.github/rulesets/main.json`, so the file matches the live ruleset Marco applied after #120 merged. `deploy-guards` passed on `main` in run 37622577098.
  - It also adds `deploy-guards` to `FLOOR` and `NEVER_CONDITIONAL` in `test_ruleset.py`.

### Rollback
Revert this PR. `roster.py` then reads every skill on disk again; there is no data or configuration step. Reverting the ruleset commit only changes the file. The live ruleset keeps `deploy-guards` until it is applied again.
