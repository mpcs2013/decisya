**Title:** feat(sharedkernel): TenantId and Result/DomainError types (0.04b)

Adds the tenant identifier and the result types every module will use.
- Requirements and traceability: `docs/requirements/phase-0/tenantid-result-types.md`
- Design: `docs/architecture/tenantid-result-types.md`
- Threat model: `docs/security/threat-models/tenantid-result-types.md`
- Review: `docs/security/reviews/32.md`
- Pipeline record: `docs/ai/pipeline/32.md`

**`TenantId`** (`Decisya.SharedKernel.Tenancy`):
- A `Guid` wrapper; `New()` mints UUIDv7.
- It accepts only the canonical hyphenated form, any GUID version. An explicit shape check rejects the `0x`, `0X` and `+` compatibility forms that `Guid.TryParseExact("D")` would otherwise accept, so two strings can never name the same tenant. Input is capped at 64 characters.
- `Guid.Empty` and `default` are rejected or fail closed on every path.
- JSON is a plain string through a built-in converter, with bounded input and fixed error messages.
- It can't be bound from a route, query or header: there is no string `TryParse`, `IParsable` or `BindAsync`. The tenant comes only from the claim (#20).
- It is logged unmasked in `tenant_id` (Marco: not PII).

**`Result`, `Result<T>` and `DomainError`** (`Decisya.SharedKernel.Results`):
- Expected failures are returned without exceptions.
- `DomainError` carries a validated `Code` and an `ErrorCategory` for the later ProblemDetails mapping (#20). Its `Message` stays internal and never reaches JSON or `ToString`.
- Getters used on the wrong branch throw fixed messages.
- Implicit conversions from a value and from an error; none to `bool`.
- The type is named `DomainError` because `Error` triggers CA1716 (a VB keyword) at this repo's analyzer level. There is no suppression.

**Decisions (Marco):**
- Guid with UUIDv7;
- hyphenated form only;
- hand-written result types, no package;
- `tenant_id` is not PII;
- the rename to `DomainError`;
- the string `TryParse` removed.
