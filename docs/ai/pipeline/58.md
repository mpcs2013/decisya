## G7 PR body draft

**Agents may not install npm packages (#58, unblocks #26)**

Closes #58

**Summary.** With host development as the default (ADR-0011), npm install scripts run as Marco's Windows user. Before the SPA (#26) brings in its npm dependency tree, the project agents lose every way to install packages. Installs become Marco's.
- **`.claude/hooks/agent_boundaries.py`:** npm is an **allow-list** for listed agents, not a list of banned verbs. npm resolves unique prefixes (`npm insta`), camelCase forms and about 40 aliases (`isnt`, `ic`, `x`), so a block-list can't keep up.
  - Allowed: `run`, `run-script`, `test`, `ls`, `outdated` and `audit` (not `audit fix`), with no flag before the verb.
  - Denied outright: `npx` (in a non-interactive shell it always fetches what it can't find) and `pnpm`, `pnpx`, `yarn`, `yarnpkg`, `bun`, `bunx`, `corepack` and `deno`.
  - Normalised like the Docker allow-list: quotes and escapes, paths, `.exe`, `.cmd`, `.ps1` and `.bat`, `npm-cli.js`, and every shell separator.
  - The main session and unlisted agents are unaffected. Denials are audited as `agent.npm`.
  - The deny reasons for npm and Docker now point to the Grep tool, for text searches that name the program.
- **Agent tools:** frontend-dev loses `npm ci` and every `npx` entry, and gets a rule that installs are Marco's. test-engineer loses `npx playwright`. Both use `npm run` scripts (`typecheck`, `lint`, `test:e2e`) that #26 defines. The roster in `docs/ai/README.md` is regenerated.
- **`.npmrc` with `ignore-scripts=true`** lands with #26, which has a comment listing G3 C-1 to C-6 (prerequisite #58; `.npmrc` before the first install; `npm audit`; the scripts review). Until then, Marco's user-level `npm config set ignore-scripts true` is in place (G3 S5, checked by G6).
