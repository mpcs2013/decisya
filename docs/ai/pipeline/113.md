## G7 PR body draft

**Let Dependabot PRs pass commitlint; stop Dependabot bumps that cannot merge**

Closes #113

**Summary.** Six of the seven open Dependabot PRs failed `build-test` because of our own setup, not the updates. Security updates would have been blocked the same way.
- **Commitlint skipped for Dependabot's own PRs only** (`ci.yml`, `build-test`):
  - Both commit-message steps skip when the PR author is `dependabot[bot]`, the event actor is `dependabot[bot]` and the branch starts with `dependabot/`. The first two are set by GitHub and cannot be faked; the branch prefix only narrows the match.
  - A human push to a Dependabot branch makes the actor a human, so the whole range is linted. A re-run keeps the original actor.
  - Every other step still runs. The check `build-test` still reports, so the ruleset is unchanged.
  - The local commitlint mirror and its goldens are unchanged; human PRs keep every rule.
- **`dependabot.yml` ignores:**
  - `typescript` and `eslint` major versions (#106, #107 fail `npm ci` until `typescript-eslint` and `eslint-plugin-jsx-a11y` support them). Patch and minor updates still come.
  - `keycloak/keycloak` in `/.devcontainer/engine` (#105): it must change together with `ContainerImages.cs`, so it's bumped by hand. Dependabot names it without the `quay.io` registry. The image CVE scan (ADR-0015) still covers this image weekly and on every image change.
- **Pin test** `.claude/tests/test_dependabot.py` (8 tests): the whole `if:` expression on both steps, `continue-on-error` only on the commitlint step, no job-level `if:` on `build-test`, the exact ignore rules per entry, and red cases.
- **Runbook:** how to handle Dependabot PRs (`@dependabot rebase` or `recreate`; never push to, close and reopen, or *Update branch* a Dependabot PR), why each ignore exists and when to lift it.

**Rollback:** revert the PR. No data or configuration step; the ruleset is unchanged.
