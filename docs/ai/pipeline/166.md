### Summary

Two dependency advisories make `build` red on every code PR (#167, #164, the Dependabot queue). This PR fixes both. Nothing is deployed, so there was no live exposure.

**1. ASP.NET Core 10.0.12 → 10.0.13**
- Advisories: GHSA-fpq8-4vhr-rcxx and GHSA-rv87-ccxw-8ggf (Critical); GHSA-494h-xx7x-5frh, GHSA-f4g7-52wc-p8x7 and GHSA-mf4x-w4gh-4656 (High). They fail the release-image scan.
- `Directory.Packages.props`: the six Microsoft 10.0.12 packages go to 10.0.13.
- `dotnet-tools.json`: dotnet-ef 10.0.13.
- `.github/release/base-images.Dockerfile`: the `aspnet` and `runtime` `10.0-noble-chiseled-extra` digests move to the 10.0.13 builds. Each digest was read two ways (registry HEAD and the MCR catalog), and the image env shows `DOTNET_VERSION`/`ASPNET_VERSION` 10.0.13.

**2. MessagePack 2.5.302 → 2.5.307** (`error NU1902`, GHSA-qhrr-8q5h-9q3h / CVE-2026-92707, Moderate)
- It arrives transitively: Aspire.Hosting 13.5.4 → StreamJsonRpc 2.25.29 → MessagePack.
- It fails restore of `Decisya.AppHost`, so `build-test`, `codeql` and `deploy-guards` go red.
- Fix: a central transitive pin (`CentralPackageTransitivePinningEnabled`), with no suppression. Drop the pin once Aspire's own graph carries ≥ 2.5.303.

**Cooldown:** Marco waived the 7-day cooldown for .NET 10.0.13 (released 2026-10-13) once, on 2026-10-17. It sets no precedent. MessagePack 2.5.307 (2026-10-03) is already past the cooldown.

**Ostium freeze:** no file under the frozen identity paths changes; only the versions of the OpenIdConnect and JwtBearer packages move. Ostium's packages need the same 10.0.13 bump; that goes through the exchange with Marco's approval.

**Rollback:** revert this PR. The advisories return and `build` goes red again. There is no data step.
