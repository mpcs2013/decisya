## G7 PR body draft

**Modules.Audit: append-only audit log for cross-tenant admin commands (0.12)**

Closes #24

**Summary.** This PR adds the audit log that platform invariant 1 requires, and audits the three cross-tenant Entitlements admin commands from #23. That meets #23's condition C-1 for #25.
- **`Decisya.Modules.Audit.Contracts`:** one write operation, `IAuditWriter.AppendAsync(AuditEntry, DbTransaction)`. `AuditEntry` carries only the target tenant, the action and the feature key. The writer fills in the actor (`ICurrentCaller`), the time (`IClock`), the trace id and the outcome itself, so a caller can't forge or omit them.
- **`AuditRecord`** (schema `audit`) is tenant-scoped to the target tenant. It has 8 columns, five check constraints, and `[Sensitive]` on the actor id. It never stores the override reason, the command payload or any free text.
- **Append-only at the role level (the Done-when).** Under **ADR-0013 (Accepted)**:
  - the migrator revokes everything on the audit table from PUBLIC and the module roles, then grants `decisya_entitlements` USAGE and INSERT only, all in one transaction;
  - no application role can UPDATE, DELETE, TRUNCATE or SELECT audit rows, and a re-run never widens anything;
  - there's no new role, password or connection string.
- **Atomic with the command (NFR-37).** Each of the three Entitlements handlers:
  - checks Forbidden, then the actor (`entitlements.actor_unknown`, never a "system" actor), then validation, with no database access before these;
  - then opens a transaction, does its work, appends one record and commits.

  If the command or the append fails, neither is kept. #23's race and re-read paths still work through EF savepoints.
- **New architecture rules:**
  - `CrossTenantAuditRule`: every `[AllowCrossTenant]` type calls the audit writer; only `AuditWriter` itself is exempt;
  - `ExplicitTransactionRule`: allowed members per type. The handlers may begin, commit and roll back; the writer may only enlist; savepoint calls are banned;
  - `RawAdoNetRule`: an allow-list. Across the modules and persistence, no raw ADO.NET or Npgsql member may be used (including COPY and data adapters), except three read-only getters.
- Only succeeded commands are audited. Refusals aren't (Marco's decision); the outcome column can add them later.
